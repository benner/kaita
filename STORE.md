# Store submission checklist

Everything below is copy-paste material for the Firefox Add-ons (AMO) and
Chrome Web Store developer dashboards. Brave, Edge, Vivaldi and Opera users
install from the Chrome Web Store.

## Build

```sh
npm run lint
npm run build
```

Upload `web-ext-artifacts/kaita_dom_history-<version>.zip` to both stores.
Bump `version` in `kaita/manifest.json` before every upload; stores reject
a version that was uploaded before.

## Listing text

- **Name:** Kaita — DOM History
- **Summary (AMO, ≤ 250 chars / CWS short description, ≤ 132 chars):**
  Record DOM snapshots of a page on demand and browse or diff them like a
  wiki page history.
- **Category:** AMO — Web Development; CWS — Developer Tools
- **Tags:** dom, diff, snapshot, history, debugging, mutationobserver
- **Homepage / support URL:** <https://github.com/benner/kaita>
- **License:** MIT

### Description

Kaita records the live DOM of a page while you work and turns it into a
revision history you can browse, diff and replay.

Click Record changes on any page. Kaita takes a snapshot immediately and
then one after every burst of DOM mutations, debounced so a thousand rapid
changes become one revision. Open View changes to see the revisions
wiki-style: pick any two as old and new and read a unified diff, view the
source of any revision, or click a row to render that revision as a page
in a sandboxed frame. Export any revision as HTML.

Recording is opt-in per tab: nothing runs on a page until you press
Record. Snapshots stay in your browser's local storage and are never
transmitted.

Useful for debugging single-page apps, understanding what a script
changed, catching layout shifts, or keeping evidence of how a page looked
at a given moment.

## Privacy

- **Privacy policy text:** the *Privacy* section of `README.md`.
- **AMO:** "Does this add-on collect or transmit user data?" → No. The
  manifest declares `data_collection_permissions.required: ["none"]`.
- **CWS privacy practices tab:** no data collected in every category;
  certify that data is not sold, not used for unrelated purposes, not used
  for creditworthiness.
- **CWS single purpose:** "Record and browse the DOM revision history of a
  page the user chooses."
- **CWS permission justifications:**
  - `activeTab` — inject the recorder into the tab the user clicked Record
    on, and read that tab's URL for the popup.
  - `scripting` — the injection itself (`scripting.executeScript`).
  - `storage` — keep the per-tab recording state in `storage.session`.
  - `unlimitedStorage` — full-page HTML snapshots exceed the default quota
    on long recordings.
  - No host permissions, no remote code.

## Source code

No build step and no minification, so neither store needs a separate
source upload. If AMO asks about `kaita/vendor/diff.js`: it is
`lib/index.mjs` from npm package `diff` 7.0.0, unmodified; see the
*Vendored dependencies* section of `README.md`.

## First-time setup

- AMO: developer account at <https://addons.mozilla.org/developers/>, free.
  Submit as *Listed*. The add-on ID `kaita@benner.github.io` is fixed from
  the first upload.
- CWS: developer account at <https://chrome.google.com/webstore/devconsole>,
  one-time registration fee. The extension ID is assigned on first upload
  and is independent of the Firefox ID.
